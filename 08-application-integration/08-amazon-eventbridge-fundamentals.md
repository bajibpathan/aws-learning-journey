# 1. What Is Event-Driven Architecture?

Event-driven architecture is a software design approach where application components communicate by producing and responding to events.

An **event** represents something that has happened in a system.

Examples include:

- An EC2 instance changes state.
- A file is uploaded to Amazon S3.
- A customer places an order.
- A payment is completed.
- A database record is updated.

Instead of continuously checking whether something has changed, applications can react when relevant events occur.

### Traditional Application Architecture

```text
Application A
     |
     v
Application B
     |
     v
Application C
```

In this architecture, one component directly communicates with another.

This can introduce dependencies between application components.

### Event-Driven Architecture

```text
                   Application A
                        |
                        v
                  Event Generated
                        |
                        v
                     Event Bus
                        |
              +---------+---------+
              |                   |
              v                   v
         Application B       Application C
```

Application A generates an event.

Other applications react to that event independently.

### Benefits

- Loose coupling
- Asynchronous processing
- Improved scalability
- Better application resilience
- Easier integration between services
- Support for serverless architectures

### Key Concept

**Event-driven architecture allows applications to react to events without requiring direct communication between every component.**

# 2. What Is Amazon EventBridge?

Amazon EventBridge is a serverless event integration service.

It connects applications using events generated by AWS services, custom applications, and supported external sources.

EventBridge can:

- Receive events
- Evaluate event rules
- Filter events
- Route matching events
- Transform event data
- Deliver events to configured targets

### Architecture

```text
                    Event Sources
                          |
             +------------+------------+
             |            |            |
             v            v            v
          Amazon EC2   Amazon S3    Application
             |            |            |
             +------------+------------+
                          |
                          v
                   Amazon EventBridge
                          |
                          v
                       Event Bus
                          |
                          v
                     Event Rules
                          |
              +-----------+-----------+
              |           |           |
              v           v           v
          AWS Lambda   Amazon SQS   Other Targets
```

### Important Concept

EventBridge acts as an intermediary between event producers and event consumers.

The source does not need to know which application will process the event.

# 3. Understanding Events

An event is a record of something that occurred.

For example:

An EC2 instance changes from the `running` state to the `stopped` state.

Amazon EventBridge can receive an event representing that state change.

### Example Event

The following is a simplified representation of an EC2 state-change event:

```json
{
  "source": "aws.ec2",
  "detail-type": "EC2 Instance State-change Notification",
  "detail": {
    "instance-id": "i-0123456789abcdef0",
    "state": "stopped"
  }
}
```

### Event Components

| Field | Description |
|---|---|
| `source` | Service or application that generated the event |
| `detail-type` | Type of event |
| `detail` | Information about the event |
| `instance-id` | EC2 instance associated with the event |
| `state` | New EC2 instance state |

### Key Concept

EventBridge evaluates event information to determine which rules match and which targets should receive the event.

# 4. What Is an Event Bus?

An **Event Bus** is a central component of Amazon EventBridge.

It receives events from supported sources and makes them available for routing through configured rules.

An event bus can receive events from multiple sources and route matching events to multiple targets.

### Architecture

```text
                     Event Sources
                           |
              +------------+------------+
              |            |            |
              v            v            v
          Amazon EC2   Amazon S3    Custom App
              |            |            |
              +------------+------------+
                           |
                           v
                       Event Bus
                           |
                  +--------+--------+
                  |                 |
                  v                 v
                Rule A            Rule B
                  |                 |
                  v                 v
              Lambda A          Lambda B
```

### Why Use an Event Bus?

An event bus enables:

- Centralized event routing
- Communication between multiple services
- Filtering based on event attributes
- Independent downstream processing
- Many-to-many event integration

### Important Concept

**Event buses are well suited for many-to-many event routing.**

This is one of the most important points highlighted in the lecture.

The default event bus receives events from supported AWS services.

### Common Use Cases

- Operational notifications

## Custom Event Bus

A custom event bus can be created to receive events from custom applications or other supported sources.

### Example

```text
                     Custom Applications
                              |
                 +------------+------------+
                 |                         |
                 v                         v
            Order Service            Payment Service
                 |                         |
                 +------------+------------+
                              |
                              v
```

# 6. What Are EventBridge Rules?

EventBridge rules determine which events should be routed to which targets.

A rule evaluates incoming events against a defined event pattern.

When an event matches the rule, EventBridge sends it to the configured target or targets.

### Architecture

```text
                     Event Source
                          |
                          v
                       Event Bus
                          |
                          v
                    EventBridge Rule
                          |
                    Match Event?
                          |
                   +------+------+
                   |             |
                   v             v
                  Yes            No
                   |             |
                   v             v
              Send to Target   No Action
```

### Example

Suppose we want to detect when an EC2 instance enters the `stopped` state.

We can create a rule that matches:

```text
Event Source: aws.ec2

Event Type: EC2 Instance State-change Notification

Instance State: stopped
```

When a matching event arrives, the rule invokes the configured target.

# 7. EventBridge Event Patterns

Event patterns define the conditions that incoming events must satisfy.

### Example

The following event pattern matches EC2 instances entering the stopped state:

```json
{
  "source": ["aws.ec2"],
  "detail-type": [
    "EC2 Instance State-change Notification"
  ],
  "detail": {
    "state": ["stopped"]
  }
}
```

### How It Works

```text
EC2 Instance
     |
     v
State Changes to Stopped
     |
     v
Event Sent to EventBridge
     |
     v
Event Pattern Evaluation
     |
     v
Pattern Matches
     |
     v
Invoke Target
```

### Important Concept

Event patterns allow EventBridge to route only relevant events.

This reduces unnecessary processing by downstream applications.

# 8. Real-World Example: EC2 Instance State Monitoring

The first example in the lecture demonstrates monitoring EC2 instance state changes.

### Business Requirement

An operations team wants to detect when an EC2 instance stops.

When the instance changes state, an automated action should occur.

For example:

- Invoke a Lambda function
- Record the event
- Trigger an operational workflow

### Architecture

```text
                    Amazon EC2 Instance
                            |
                            v
                      State: Running
                            |
                            v
                      State: Stopped
                            |
                            v
                     State Change Event
                            |
                            v
                   Default Event Bus
                            |
                            v
                    EventBridge Rule
                            |
                            v
                       AWS Lambda
                            |
                            v
                     Automated Action
```

### Workflow

1. An EC2 instance is running.
2. The instance changes to the stopped state.
3. Amazon EC2 generates a state-change event.
4. The event reaches the default EventBridge event bus.
5. EventBridge evaluates the configured rules.
6. A matching rule identifies the event.
7. EventBridge invokes the Lambda target.
8. Lambda performs the configured action.

### Important Concept

EventBridge allows applications to react to infrastructure changes without continuously polling EC2 for instance status.

# 9. Filtering Events for Specific EC2 Instances

The previous event pattern matches stopped-state events for EC2 instances generally.

However, an operations team may want to monitor only a specific instance.

### Example

```json
{
  "source": ["aws.ec2"],
  "detail-type": [
    "EC2 Instance State-change Notification"
  ],
  "detail": {
    "instance-id": [
      "i-0123456789abcdef0"
    ],
    "state": ["stopped"]
  }
}
```

### Result

The rule matches only when the specified EC2 instance enters the stopped state.

### Architecture

```text
                  EC2 State Change Events
                            |
                            v
                     Default Event Bus
                            |
                            v
                       Event Rule
                            |
                  +---------+---------+
                  |                   |
                  v                   v
            Matching Instance    Other Instances
                  |                   |
                  v                   v
             Invoke Lambda         Ignore
```

### AWS Exam Point

**Use EventBridge event patterns to filter events based on their attributes.**

# 10. EventBridge Event Transformation

Amazon EventBridge can transform event data before delivering it to a target.

This is useful when the target requires only certain fields or a different input format.

### Example

An EC2 state-change event contains multiple fields.

However, a Lambda function may only need:

- Instance ID
- Instance state

### Architecture

```text
                      EC2 Event
                          |
                          v
                    EventBridge Rule
                          |
                          v
                    Input Transformer
                          |
                          v
                   Transformed Event
                          |
                          v
                       AWS Lambda
```

### Example Input

```json
{
  "source": "aws.ec2",
  "detail": {
    "instance-id": "i-0123456789abcdef0",
    "state": "stopped"
  }
}
```

### Example Transformed Output

```json
{
  "instanceId": "i-0123456789abcdef0",
  "currentState": "stopped"
}
```

### Benefits

- Simplifies target processing
- Reduces unnecessary event data
- Supports target-specific input formats
- Improves integration flexibility

### Important Distinction

An EventBridge input transformer can reshape event data.

More complex enrichment involving additional services is a capability associated with EventBridge Pipes, discussed later in this lesson.

### Architecture

```text
                            |

                            |
                            v
                      Execute Task
```

### Important Concept

Scheduled events trigger operations based on time rather than an event generated by an application or AWS resource.

# 12. Cron Expressions

A cron expression defines a schedule based on specific time values.

For example:

- Minute
- Hour
- Day of month
- Month
- Day of week
- Year

### AWS EventBridge Cron Format

```text
cron(minutes hours day-of-month month day-of-week year)
```

### Example

Run a task every day at 5:00 PM UTC:

```text
cron(0 17 * * ? *)
```

### Explanation

| Field | Value | Meaning |
|---|---|---|
| Minutes | 0 | At minute zero |
| Hours | 17 | At 17:00 |
| Day of Month | * | Every day |
| Month | * | Every month |
| Day of Week | ? | No specific day-of-week selection |
| Year | * | Every year |

### Important Note

The expression above uses UTC.

For timezone-aware scheduling, Amazon EventBridge Scheduler supports configurable time zones.

---

# 13. Rate Expressions

A rate expression defines a recurring interval.

Instead of specifying an exact calendar time, it specifies how frequently an operation should run.

### Examples

Run every ten minutes:

```text
rate(10 minutes)
```

Run every hour:

```text
rate(1 hour)
```

Run every day:

```text
rate(1 day)
```

### Comparison

| Feature | Cron Expression | Rate Expression |
|---|---|---|
| Purpose | Run at specific times | Run at recurring intervals |
| Example | Every day at 5 PM | Every 60 minutes |
| Scheduling Style | Calendar-based | Interval-based |
| Common Use Case | Daily batch processing | Periodic background jobs |

### AWS Exam Point

**Cron = Execute at a specific scheduled time.**

**Rate = Execute at a recurring interval.**

# 15. EventBridge Rules vs EventBridge Scheduler

The lecture discusses scheduled EventBridge rules.

AWS also provides a dedicated scheduling capability called **Amazon EventBridge Scheduler**.

### EventBridge Scheduled Rules

Scheduled rules can trigger targets using cron or rate expressions.

They are associated with the default event bus.

### EventBridge Scheduler

EventBridge Scheduler is a dedicated service for creating scheduled tasks.

It supports:

- One-time schedules
- Recurring schedules
- Cron expressions
- Rate expressions
- Configurable time zones
- Flexible delivery windows

### Comparison

| Feature | EventBridge Scheduled Rules | EventBridge Scheduler |
|---|---|---|
| Recurring Scheduling | Supported | Supported |
| Cron Expressions | Supported | Supported |
| Rate Expressions | Supported | Supported |
| One-Time Schedules | Not the primary capability | Supported |
| Time Zone Configuration | UTC-based | Configurable |
| Flexible Delivery Windows | Not supported in the same way | Supported |
| Recommended for New Scheduling Workloads | Generally prefer Scheduler | Yes |

### Important Clarification

For new applications requiring scheduled tasks, AWS generally recommends EventBridge Scheduler over legacy scheduled rules.

The lecture introduces the underlying scheduling concepts, which apply to both approaches.

# 16. What Are Amazon EventBridge Pipes?

The final section of the lecture introduces a feature described as point-to-point event integration.

The AWS feature being explained is:

**Amazon EventBridge Pipes**

EventBridge Pipes connects a supported event source to a single target.

It can optionally:

1. Filter events
2. Transform events
3. Enrich events
4. Deliver events to a target

### Architecture

```text
                       Event Source
                            |
                            v
                     EventBridge Pipe
                            |
                            v
                         Filtering
                            |
                            v
                    Optional Enrichment
                            |
                            v
                      Transformation
                            |
                            v
                           Target
```

### Key Concept

**EventBridge Pipes are designed for point-to-point integrations between supported sources and targets.**

This differs from event buses, which are designed for many-to-many event routing.

---

# 17. EventBridge Pipes Components

The lecture introduces several important components of a Pipe.

## Source

The source provides events to the Pipe.

## Filtering

Filtering determines which events should continue through the Pipe.

## Enrichment

Enrichment adds information to an event.

For example, a Lambda function may retrieve additional details related to the event.

## Transformation

Transformation changes the event data into a format expected by the target.

## Target

The target receives the processed event.

### Architecture

```text
                     Source
                       |
                       v
                Event Filtering
                       |
                       v
              Optional Enrichment
                       |
                       v
                Transformation
                       |
                       v
                     Target
```

### Example

An event contains a customer ID.

The target application also requires customer information.

An enrichment step could retrieve additional information before the event is delivered.

### Conceptual Workflow

```text
Incoming Event
      |
      v
Customer ID
      |
      v
Enrichment Function
      |
      v
Customer Information Added
      |
      v
Target Application
```

### Additional AWS Clarification

EventBridge Pipes supports specific AWS services as sources, enrichment integrations, and targets.

Not every AWS service can be used in every position.

# 18. Event Bus vs EventBridge Pipes

This is one of the most important comparisons in the lesson.

## Event Bus

An event bus is suitable for routing events from multiple sources to multiple targets.

```text
                  Event Sources
                        |
             +----------+----------+
             |          |          |
             v          v          v
          Source A   Source B   Source C
             |          |          |
             +----------+----------+
                        |
                        v
                     Event Bus
                        |
             +----------+----------+
             |          |          |
             v          v          v
           Rule A     Rule B     Rule C
             |          |          |
             v          v          v
          Target A   Target B   Target C
```

## EventBridge Pipes

A Pipe connects a supported source to one target.

```text
                    Event Source
                         |
                         v
                  EventBridge Pipe
                         |
                         v
                      Filtering
                         |
                         v
                 Optional Enrichment
                         |
                         v
                       Target
```

### Comparison

| Feature | Event Bus | EventBridge Pipes |
|---|---|---|
| Integration Pattern | Many-to-many | Point-to-point |
| Sources | Multiple event publishers | One configured source |
| Targets | Multiple targets through rules | One configured target |
| Event Filtering | Supported | Supported |
| Event Transformation | Supported | Supported |
| Event Enrichment | Requires additional integration design | Built-in optional enrichment step |
| Main Purpose | Event routing | Source-to-target integration |
| Common Use Case | Distributed event-driven applications | Connect and process events between supported services |

### AWS Exam Point

**Event Bus = Many-to-many event routing**

**EventBridge Pipes = Point-to-point integration with filtering, transformation, and optional enrichment**

# 19. Amazon EventBridge vs SNS vs SQS

We have now covered three important AWS messaging and integration services.

Let's compare them.

| Feature | Amazon SQS | Amazon SNS | Amazon EventBridge |
|---|---|---|---|
| Primary Purpose | Message queuing | Message distribution | Event routing |
| Messaging Model | Pull-based | Push-based | Event-driven |
| Main Component | Queue | Topic | Event bus, rule, or Pipe |
| Multiple Targets | Requires additional architecture | Supported through subscriptions | Supported through event bus rules |
| Message Filtering | Consumer-side or application logic | Subscription filter policies | Event patterns and Pipe filtering |
| Message Buffering | Yes | Not a general-purpose queue | Not a general-purpose queue |
| Scheduled Events | No native general scheduler | No native general scheduler | Supported through scheduling capabilities |
| Event Transformation | Application-dependent | Limited message formatting options | Supported |
| Event Enrichment | Application-dependent | Application-dependent | Supported through Pipes |
| Common Use Case | Background processing | Notifications and Fan-Out | Event-driven application integration |

### Simplified Comparison

```text
Amazon SQS
-----------
Producer -> Queue -> Consumer

Amazon SNS
-----------
Publisher -> Topic -> Multiple Subscribers

Amazon EventBridge
------------------
Event Sources -> Event Bus -> Rules -> Targets

Amazon EventBridge Pipes
------------------------
Source -> Filter -> Enrich -> Transform -> Target
```

# 21. Common Mistakes

### 1. Confusing EventBridge with SQS

EventBridge routes events.

SQS stores messages until consumers retrieve them.

### 2. Confusing EventBridge with SNS

Both services support event distribution.

However, EventBridge emphasizes rule-based event routing and integration with supported event sources.

### 3. Assuming Every Event Is Delivered to Every Target

EventBridge rules determine which events match and which targets receive them.

### 4. Confusing Event Buses with Pipes

Event buses support many-to-many routing.

Pipes support point-to-point integrations.

### 5. Assuming EventBridge Automatically Performs Complex Data Enrichment

EventBridge Pipes provides an enrichment integration point.

The enrichment logic must still be implemented using an appropriate service.

### 6. Confusing Cron and Rate Expressions

Cron expressions define calendar-based schedules.

Rate expressions define recurring intervals.

### 7. Ignoring Time Zones

EventBridge scheduled rules use UTC-based scheduling.

EventBridge Scheduler supports configurable time zones.

### 8. Assuming EventBridge Is a General-Purpose Message Queue

EventBridge is primarily an event integration and routing service.

Use SQS when applications require durable message buffering and consumer-controlled processing.

# ❓ Interview Questions

### Q1. What is Amazon EventBridge?

Amazon EventBridge is a serverless event integration service used to connect application components through events.

### Q2. What is event-driven architecture?

An architecture where applications communicate by producing and responding to events.

### Q3. What is an event?

A record representing something that happened in an application or system.

### Q4. What is an EventBridge event bus?

A component that receives events and makes them available for routing through configured rules.

### Q5. What is the default event bus?

The event bus provided by EventBridge for supported AWS service events.

### Q6. What is a custom event bus?

An event bus created to receive and route events from custom applications or other supported sources.

### Q7. What is an EventBridge rule?

A configuration that matches incoming events and routes them to specified targets.

### Q8. What is an event pattern?

A set of conditions used to determine whether an incoming event matches a rule.

### Q9. Can EventBridge monitor EC2 state changes?

Yes. EventBridge can match EC2 instance state-change events.

### Q10. Can EventBridge invoke AWS Lambda?

Yes. Lambda is a supported EventBridge target.

### Q11. What is event transformation?

Changing event data into a format required by a target.

### Q12. What is an EventBridge scheduled event?

A time-based trigger used to invoke a target at a scheduled time or interval.

### Q13. What is a cron expression?

An expression that defines a calendar-based schedule.

### Q14. What is a rate expression?

An expression that defines how frequently a recurring task should run.

### Q15. What is EventBridge Scheduler?

A dedicated AWS scheduling service for one-time and recurring tasks.

### Q16. What are EventBridge Pipes?

A feature that connects supported event sources to targets through point-to-point integrations.

### Q17. What capabilities do EventBridge Pipes provide?

Filtering, transformation, and optional enrichment.

### Q18. What is the difference between an event bus and a Pipe?

An event bus supports many-to-many event routing, while a Pipe connects one configured source to one target.

### Q19. What is the difference between SNS and EventBridge?

SNS distributes published messages to subscribers, while EventBridge uses event rules to route matching events to targets.

### Q20. When should SQS be used instead of EventBridge?

When applications need message buffering and consumer-controlled processing.
